# 自测与内测手册

面向你自己：先把功能点一遍，再拉一小波人试用。

---

## 0. 先把服务跑起来

```bash
cd openbox-service
npm start
```

启动后会打印三行地址（你当前配置是只能本机访问）：

```
   落地页    http://127.0.0.1:8788/
   接单后台  http://127.0.0.1:8788/admin.html
```

> **你的后台口令在 `.env` 里**（`ADMIN_PASSWORD` 那一行）。仓库里不放真实口令，本机配置文件不提交。
> 想换：改 `.env` 里那一行，重启即可。

**关掉服务**：在跑服务的终端按 `Ctrl + C`。

## 1. 自己测：按顺序点一遍

### A. 落地页

| # | 要做的事 | 期望看到 |
|---|---|---|
| 1 | 打开 `http://127.0.0.1:8788/` | 顶部有一条橙色「内测版」提示；首屏渐显 |
| 2 | 搜索框输入 `cursor` | 下拉出现 Cursor 等结果，最多 6 条 |
| 3 | 再输入 `画图` / `语音` 这类中文 | 按分类也能搜到 |
| 4 | 按回车 | 该工具进入下方清单 |
| 5 | 点分类标签（命令行/绘图/…） | 卡片按类筛选；再点「全部」恢复 |
| 6 | 鼠标悬停卡片，点右上角 ✕ | 卡片被移出清单 |
| 7 | 看屏幕底部浮条 | 数量、预计耗时、推荐套餐随选择实时变 |
| 8 | 点浮条或「打开待装清单」 | 右侧抽屉打开，列出已选工具 |
| 9 | 在抽屉里改系统 / 电脑基础 | 选中态高亮 |
| 10 | 联系方式留空，点「提交预约单」 | 红字提示「留个联系方式…」，不提交 |
| 11 | 填个联系方式，再提交 | 出现 ✅ 并给出一串 `OB-日期-XXXX` 单号 |

### B. 接单后台

| # | 要做的事 | 期望看到 |
|---|---|---|
| 1 | 打开 `http://127.0.0.1:8788/admin.html` | 先看到口令登录页 |
| 2 | 故意输错口令 | 提示「口令不正确」 |
| 3 | 输对 `.env` 里的口令 | 进入看板 |
| 4 | 对账 | 「累计订单」「今日新增」比刚才多 1 单；金额与落地页显示一致 |
| 5 | 点「待接单」标签 | 只剩待接单的；标签上带数量 |
| 6 | 搜索框输入刚才的单号 | 精确定位到那一单 |
| 7 | 点任意一行 | 右侧弹出详情：联系方式、服务端核定报价、工具明细、流转时间线 |
| 8 | 点「接单」 | 状态变「已接单」，看板「进行中」+1 |
| 9 | 再点「完成」 | 状态变「已完成」，出现在营收里 |
| 10 | 找一单点「取消」 | 先弹确认框，确认后变「已取消」 |
| 11 | 按 F5 刷新 | 仍然是登录状态（令牌在 sessionStorage 里） |
| 12 | 点「退出」 | 回到登录页 |

> 第 8~10 步如果按钮点了没反应，多半是服务停了 —— 看右上角是否变成「连接中断」。

### C. 异常与边界（这些最能测出问题）

| # | 要做的事 | 期望看到 |
|---|---|---|
| 1 | 一个工具都不选就提交 | 提示「还没选工具」，并自动滚回工具库 |
| 2 | 备注里贴 600 个字 | 后端拒绝，提示备注太长（上限 500） |
| 3 | **把服务停掉**（Ctrl+C），再点提交 | 降级成本地文本 + 自动复制，提示「网络不通…」。**下单不能丢** |
| 4 | 停服状态下刷新落地页 | 页面照常显示，只是顶部内测横幅消失（它来自后端） |
| 5 | 在后台把一单改成「已完成」，再试着取消 | 被拒（终态不可回退） |

### D. 对账

```bash
npm run export
```

会导出 `exports/orders-日期.csv`（带 BOM，Excel 直接双击不会乱码），并打印营收合计。
拿它和后台看板的「订单总额」对一下数。

### E. 想跑一遍自动化回归

```bash
npm test        # 接口层：109 项断言（隔离实例，不碰你的订单）
npm run e2e     # 浏览器层：无头 Edge 像真人一样点完整条链路，32 项断言
```

`npm run e2e` 会在**正式库里**真实创建一单（联系方式带 E2E 标记），跑完自动删掉恢复原状。
它每次要消耗 3 次登录额度，**连跑几次会撞登录限流**（提示「操作太频繁」）——
限流计数在服务进程内存里，把服务 `Ctrl+C` 停掉再 `npm start` 就清零了。

## 2. 内测准备

### 第一步：让局域网能访问

改 `.env`：

```ini
HOST=0.0.0.0
```

重启服务，启动横幅会多打印一行局域网地址，形如：

```
   局域网    http://192.168.1.7:8788/
```

**这一行就是发给测试者的链接。**

### 第二步：放行防火墙（第一次访问会卡在这）

Windows 第一次被外部访问时会弹窗问「是否允许」，**点「允许访问」**即可。

如果没弹窗或点错了，用**管理员**身份运行 PowerShell / CMD 补一条规则：

```cmd
netsh advfirewall firewall add rule name="OpenBox 8788" dir=in action=allow protocol=TCP localport=8788
```

不需要了就删掉：

```cmd
netsh advfirewall firewall delete rule name="OpenBox 8788"
```

### 第三步：自己先用手机验一遍

连同一个 Wi-Fi，用手机浏览器打开那个局域网地址。

- 打得开 → 通了，可以发给测试者
- 打不开 → 九成是防火墙（第二步）或手机不在同一网络（注意别连了 5G 以外的访客网络）

### 第四步：发链接

建议连同一句话一起发：

> 帮我试试这个小工具，我做的。上面勾几个你想装的 AI 工具、留个联系方式就能提交。
> 现在还是内测版，随便点、点坏了也没关系，哪里看不懂直接跟我说。

链接记得带上 `http://`，微信里有时不会自动识别。

### 第五步：盯单

后台开着就行，**每 30 秒自动刷新**，有人提交就会冒出来。

> 内测期间建议每收几单就 `npm run export` 导一次 CSV —— 比数据库文件方便看，也顺手当备份。

### 内测结束后

改 `.env` 把横幅关掉，对外显示就正式了：

```ini
BETA_MODE=off
HOST=127.0.0.1        # 不再对外暴露就改回来
```

## 3. ⚠️ 内测期间必须知道的三件事

1. **只在你自己家的 Wi-Fi 下开 `HOST=0.0.0.0`。**
   咖啡馆、机场、酒店这类公共网络下别开 —— 同一网络的人都能访问你的落地页和后台登录页。

2. **一个 IP 十分钟最多提交 20 次下单。**
   测试者反复提交、或者你拿同一个网络测很多次，会撞上限流（提示「请稍后再试」）。
   内测人手多的话，临时把 `.env` 里的 `ORDER_RATE_MAX` 调大：

   ```ini
   ORDER_RATE_MAX=200
   ```

   同一个限制也作用在登录上（`LOGIN_RATE_MAX=10`），口令输错太多次要等十分钟。

3. **后台口令就是这个站点的唯一防线。**
   现在这条口令有 23 位，够用。别改成 `123456` 之类 —— 后台能看到所有测试者的联系方式。

## 4. 数据：备份、导出、清空

| 想做什么 | 怎么做 |
|---|---|
| 订单存在哪 | `data/openbox.db`（连同 `-wal` / `-shm` 一起） |
| 备份 | 停掉服务，把整个 `data/` 目录复制一份到别处 |
| 导出成表格 | `npm run export` → `exports/orders-*.csv` |
| 清空重来 | `npm run reset-db`（会要求手动输入 `yes` 确认） |
| 灌一批演示数据 | `npm run seed`（需服务在跑） |
| 改完 UI 想重看截图 | `npm run shots` |

> `data/` 和 `exports/` 都已在 `.gitignore` 里，不会被提交。
> `exports/` 里的 CSV **含测试者的微信号/手机号**，别随手发到群里。

## 5. 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 启动报「端口已被占用」 | 8788 被别的程序占了 | 改 `.env` 的 `PORT`，或关掉占用的程序 |
| 忘了后台口令 | —— | 改 `.env` 的 `ADMIN_PASSWORD`，重启覆盖 |
| 手机打不开局域网地址 | 防火墙 / 不同网络 / HOST 没改 | 见上面「内测准备」第二、三步 |
| 后台右上角一直「连接中断」 | 服务停了或崩了 | 看启动终端有没有报错；重启服务 |
| 页面字体和截图不太一样 | 字体走 Google Fonts，网络慢或断网 | 不影响功能，会用系统字体兜底 |
| 提交时提示「网络不通，已生成文本」 | 后端没起 | 这是设计好的降级：文字已复制到剪贴板，可以直接发给你 |
| 提交提示「请稍后再试」 | 撞下单限流了 | 等十分钟，或调大 `ORDER_RATE_MAX` |
| 登录提示「尝试过于频繁」 | 撞登录限流了 | 等十分钟，或重启服务（限流在内存里，重启即清零） |
| 改完 `.env` 没变化 | 没重启 | `Ctrl+C` 后重新 `npm start` |

## 6. 让测试者说什么才有用

内测最怕听到「挺好的」。按这几条追问，能问出真东西：

1. **看懂了吗** —— 「你第一眼觉得这个页面是干嘛的？」
2. **哪一步卡住** —— 「从打开到提交，有没有哪一步你不确定该点什么？」
3. **敢不敢填** —— 「让你填一个微信号进去，你犹豫了吗？为什么？」
4. **信不信** —— 「页面里哪句话让你觉得不太可信？」
5. **值不值** —— 「如果这套服务收 99 块，你觉得贵、便宜、还是没法判断？」
6. **真实需求** —— 「你自己最想装的是哪个工具？为什么是它？」

第 3、4 条是重点：你这门生意真正的门槛不是技术，是**陌生人愿不愿意把电脑交给你**。
